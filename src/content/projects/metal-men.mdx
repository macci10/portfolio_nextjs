Forking an actively developed open-source client is easy; staying on it isn't.
The work that mattered here was the upgrade pipeline — a structured way to
absorb continuous upstream FluffyChat changes without the fork drifting into
something unmergeable.

The failure mode is well known and slow: you customise the UI, upstream
refactors the widget tree, your next merge is a hundred conflicts, you skip it,
and six months later you are running a client that can no longer take security
fixes. Avoiding that is mostly discipline about where customisation is allowed
to live. Keeping the changes concentrated and boundary-shaped rather than
sprayed through the tree is what took integration time per release down by
around 70%, across 7–8 production updates.

Underneath, it is Matrix: real-time messaging with cross-device state
synchronisation, and Hive holding local state.

## CI/CD

CI/CD across four build targets. GitHub Actions runs static analysis, unit
tests, and Android integration tests on an emulator, then builds Android, iOS,
web, and Linux. Fastlane automates Android release signing and Play Store track
promotion through internal → beta → production. Web deploys to Firebase Hosting
on tag. iOS is compile-verified in CI with `--no-codesign` and submitted to
TestFlight through a Fastlane lane run locally.
