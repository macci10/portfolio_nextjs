I led the mobile team of three engineers and owned architecture, code review,
and the release cadence across the full lifecycle. The app puts clinical
guidance in front of doctors at the point of care, which sets the reliability
bar: a runtime error isn't a bad user experience, it's a clinician seeing the
wrong guidance.

That bar is what drove the TypeScript migration. A React Native codebase
written in JavaScript accumulates a lot of implicit shape assumptions, and the
ones that survive to production are exactly the ones that only break on unusual
data. Moving to TypeScript and functional Hooks under clean
architecture principles cut the production crash rate by 40% and roughly halved
feature delivery time.

The variant work is the piece I'd point at in an interview. AvoMD needed to ship
as three distinct apps — the main product, Columbia Psych, and Preoperative Eval
— each with its own identity and content set. The obvious answer is three
codebases, and the obvious answer would have tripled the maintenance. Xcode
build configurations and Android Studio flavors gave all three from one
codebase instead.

Provisioning was the least glamorous and most useful thing I built: an
HTTP-triggered Cloud Function that read a Google Sheet and performed bulk
writes into the Firebase Realtime Database through the Admin SDK. Clients
updated live.
